# correlation-id-middleware-ts

Reads an incoming correlation ID header from a Node.js HTTP request, or generates a new UUID v4 when one is absent or malformed, then attaches the resolved value to the request object and echoes it back as a response header.

```js
import http from 'node:http';
import { createCorrelationIdMiddleware } from 'correlation-id-middleware-ts';

const middleware = createCorrelationIdMiddleware({
  headerName: 'x-correlation-id',
  propertyName: 'correlationId',
});

const server = http.createServer((req, res) => {
  middleware(req, res, () => {
    console.log(req.correlationId); // the resolved UUID
    res.end('ok');
  });
});
```

## Why this exists

Every multi-service backend needs a way to thread a single identifier through logs across hop boundaries. The obvious approach — "grab a header, or make one" — has exactly one hard decision: do you trust whatever the client sent, or do you validate it? This library validates. An attacker or a misconfigured proxy can send an arbitrary string in a header; echoing it verbatim into your logs and downstream calls lets them inject log entries that look like real traffic. By accepting only well-formed RFC 4122 UUIDs, we reject injection garbage while still propagating identifiers generated by any compliant UUID library, regardless of version (v1 through v5 and the nil UUID are all accepted, since a correlation ID is not a secret).

The trade-off: if an upstream service sends a non-UUID correlation identifier (say, a short numeric token), this middleware will silently replace it. That is deliberate. If your system relies on non-UUID correlation tokens, this is the wrong library.

## The awkward edge

The correlation ID is attached to the request as a **non-enumerable** property. This means `console.log(req)` and `JSON.stringify(req)` will not show it — only an explicit `req.correlationId` access will. If you need it in serialized output, read it explicitly.

Node lowercases all incoming header names, so the middleware compares against a lowercased copy of the configured `headerName`. A header configured as `X-Correlation-Id` will still match an incoming `x-correlation-id`.

## Exports

- `createCorrelationIdMiddleware(options?)` — returns `(req, res, next) => void`.
- `uuid()` — generates a v4 UUID via `crypto.randomUUID`.
- `isUuid(value)` — returns `true` for a case-insensitive RFC 4122 UUID string, `false` otherwise.

## Options

| Option           | Default             | Purpose                                              |
|------------------|---------------------|------------------------------------------------------|
| `headerName`     | `'x-correlation-id'`| Request/response header name.                        |
| `propertyName`   | `'correlationId'`   | Name of the non-enumerable property attached to `req`.|
| `generate`       | `uuid`              | Factory called when no valid ID is incoming.         |
